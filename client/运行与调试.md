# 客户端运行与调试

下面的命令都在 `client/` 目录下执行。两个客户端：

| | 用户端（康养看护） | 运维端（雷达运维） |
|---|---|---|
| 目录 | `apps/user` | `apps/ops` |
| 调试端口 | 1430 | 1420 |
| 安装包名 | RadarCare | RadarOps |

两个端口不同，可以同时运行。

## 第一次使用

需要 Node 22+、Rust（MSVC 工具链）、VS 2022 的"使用 C++ 的桌面开发"。

```bash
cd client
npm install
```

## 浏览器调试（日常改界面用这个，最快）

只启动前端，不编译 Rust：

```bash
npm run web:ops     # 运维端，打开 http://localhost:1420
npm run web:user    # 用户端，打开 http://localhost:1430
```

- 请求经过 vite 的 `/__proxy` 转发到 rd.igoodlife.com（正式环境），登录页上的服务器选项不起作用。
- 登录状态存在当前标签页的 sessionStorage（`RC_DEV_SESSION`），刷新页面不会掉登录，关闭标签页后要重新登录。
- 改代码后页面自动热更新。
- 托盘、系统通知等桌面功能在浏览器里没有，要用下面的桌面调试。

## 桌面调试

启动真正的桌面窗口（第一次会编译 Rust，需要几分钟）：

```bash
npm run ops
npm run user
```

- **Windows 请在 PowerShell 或 cmd 里运行**。Git Bash 里 Git 自带的 `link.exe` 会挡住 MSVC 链接器，Rust 编译会失败。
- 前端代码改了会热更新；`src-tauri/` 里的 Rust 代码或配置改了会自动重新编译并重启窗口。
- 用户端关闭窗口只是缩到托盘，退出要在托盘菜单里点"退出"。用户端只允许运行一个实例。
- 桌面客户端的登录状态只在内存里，关闭客户端即退出。

## 类型检查

两端都做类型检查并构建前端（不打安装包）：

```bash
npm run typecheck
```

只做类型检查、只查某一端时：

```bash
npx tsc --noEmit -p apps/ops
```

## 打安装包

只在需要发给别人时打包，平时调试不用：

```bash
npm run build:ops
npm run build:user
```

- 同样要在 PowerShell 或 cmd 里运行。
- 打包的客户端固定连正式环境，没有服务器选择。
- 安装包输出到 `client/target/release/bundle/`：
  - `nsis/RadarOps_<版本>_x64-setup.exe`（安装程序，一般发这个）
  - `msi/RadarOps_<版本>_x64_en-US.msi`
- 版本号在 `apps/<端>/src-tauri/tauri.conf.json` 的 `version`，发新包前先改版本号。

## 常见问题

| 现象 | 处理 |
|---|---|
| 启动时报端口 1420 / 1430 被占用 | 已经有一个同端的调试在运行，关掉它，或直接用已打开的那个 |
| `cargo` / `link.exe` 报链接错误 | 换到 PowerShell 或 cmd 里运行 |
| 浏览器调试时接口返回 401 | 登录过期，重新登录 |
| 浏览器调试时没有托盘、通知 | 正常，这些只在桌面客户端里有 |
