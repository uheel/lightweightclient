# 房间装修（摆家具）

目的：平面图上除了检测区域，还能看出这是一间什么样的房，比如床在哪、马桶在哪、沙发在哪，一眼就能认出来。装修只用于显示，**不下发到设备**，和区域里的"7 家具"也不是一回事。

平台这边的数据格式和限制见 [site-analysis.md](site-analysis.md) 的"家具图库和布置元素能存哪些字段"。

## 数据：存在平台的房间布置里

- 每件家具是 `elements` 里的一个顶层元素，平台网页端的房间详情和户型设计也能看到：
  - 平台图库里有对应图片的家具，存成 `type: 4`，`src` 填 `/sapi/oss/<图库 imageUrl>`
  - 图库里没有的（淋浴、窗、隔墙），存成 `type: 2` 矩形，平台上显示成一个方块
  - `name` 填家具的中文名（"双人床"），`id` 用 32 位十六进制，`x / y / width / height` 单位厘米，`rotation` 绕左上角旋转
- 平台会把自定义字段丢掉，所以"这是什么家具"按下面的顺序认：
  1. `name` 是我们目录里的家具名 → 就是这种家具
  2. `src` 是图库里的线稿图 → 按对照表认（平台网页端摆的线稿家具走这一步）
  3. `src` 是图库里的写实照片，或 `name` 带"（写实）" → 写实元素，直接画原图
  4. 都认不出 → 照原样画平台的图片（type 4）或矩形（type 2）
- 图形：文字存 `type: 5`（`text`、`fontSize`、`fill`，`width / height` 按字数估，平台不算文字宽度）；矩形、圆形存 `type: 2`，`name` 是"矩形""圆形"，带 `fill / stroke / strokeWidth / cornerRadius`。圆形是圆角 = 边长一半的正方形，改大小时保持正圆
- 底图：`roomStyle` 改成 `type: 4` + `src`（平台的户型底图就是这样存的），按房间尺寸铺满。图片压缩成 webp 后传到机构文件管理的"运维端"文件夹；选图时就上传，点保存才写进布置。换底图不删旧文件，"复制布置"建的房间可能还在用；去掉底图时外框恢复 `type: 2` 白底
- 保存装修时重新取一次最新布置，只替换顶层的 type 4 / type 2 / type 5 元素（家具放在最前面，画在雷达和区域下面）和改过的底图，雷达、组合原样保留，所以不会覆盖别处刚改的区域
- 保存装修不会碰设备，不需要等应答

## 图标：客户端自己画

- 每种家具一个按宽高画的俯视线稿 SVG（床有枕头和被子，沙发按长度分座位，餐桌按大小摆椅子），拉长、拉宽以后细节不会变形
- 颜色走 CSS 类，浅色和监控模式的深色各有一套
- 在平面图里放在底图之上、区域和雷达之下
- 房间底图（网格、户型底图图片、家具和文字、墙）是一个公共组件 `rooms/RoomBackdrop.tsx`：诊断和监控的平面图、楼宇面板的预览、装修编辑器、设备安装设置的区域画布都用它，各自只在上面叠区域、雷达、实时目标或可拖动的家具。区域画布按分米、以雷达为原点画，底图用 `translate + scale(0.1)` 套进去，淡色、不接鼠标，画区域时能对着床和门画
- 时间回溯：房间在客户端装修过（有家具的 `name` 是目录里的家具名，`decoratedInClient`）时，家具和墙用同一个底图组件画在 SVG 层（地板画布之上、区域和雷达画布之下）；没装修过照旧在画布上画平台图库的原图。平台网页端摆的家具没有这样的 `name`，在客户端装修里保存一次后，认得出的都会写上 `name`，就算装修过了
- 朝向和平台图库的图一致（靠墙一边在上）。门分"门"（左铰链，对应图库门 2）和"门（右开）"（右铰链，对应门 1），因为平台存不下镜像

## 编辑器

入口有两个，打开的是同一个弹窗（`rooms/furniture/DecorDialog.tsx`）：
- 运维端 › 楼宇 › 点房间 › 右侧面板的"装修"：面板里有一张小平面图预览（显示摆了几件家具），点预览或"装修"按钮都能打开，保存后预览跟着更新
- 运维端 › 诊断（房间布置）› 平面图右上角"装修"

- 左边是家具面板：最上面是图形（文字、矩形、圆形），下面可切换线稿（卧室、客厅、卫浴、厨房、门窗墙五组）和写实（图库里透明底的俯视照片 50 件，长度按图片比例算，不变形）。点一下放到房间中间，也可以拖到图上指定位置
- 画布下方"上传底图 / 换底图 / 去掉"；图片比例和房间差 5% 以上时提醒会被拉伸
- 选中后可以：拖动（按 5 cm 对齐，离墙 10 cm 以内自动贴墙）、拖右下角改大小、旋转 90°、复制（Ctrl+D）、删除（Delete）、方向键微调（按住 Shift 一次 10 cm）；右边面板可以直接填宽、长（厘米）
- 选中时四个方向标出到最近的墙或家具的距离（cm，按外接框算，已经贴上的方向不标），右边面板能直接填"离左墙""离上墙"，并显示离右墙、离下墙
- 层级：右边面板置顶 / 上移 / 下移 / 置底，快捷键 `]`、`[`、`Ctrl+]`、`Ctrl+[`。`elements` 的顺序就是层级，靠后的盖住靠前的。上移、下移一次越过一件有重叠的家具，这个方向没有重叠的家具时按钮禁用。门固定在墙和其他家具上面（门洞要挖开墙），只调门和门之间的前后
- 滚轮以鼠标位置缩放（最多 10 倍）、拖空白处平移、底部按钮缩放和"适应"，双击空白处回到整间房；标注文字和手柄按屏幕像素定大小，缩放后照样清楚
- 背景淡淡地画出雷达的监测边界和区域，方便对着床位摆
- 点保存才写平台；有没保存的改动时关窗口会先问

## 验证（2026-10-24，李虎机构 601，测完已恢复成空布置）

- 摆 13 件、拖动、贴墙、旋转 90°、拖角改尺寸、复制、删除后保存：平台读回 `name`、32 位 `id`、`rotation` 都在，淋浴和窗存成矩形；平台网页端房间详情按图库图片显示出来
- 101房间里平台网页端摆的马桶、洗手台、门、床，客户端按 `src` 认出来并换成图标；监控模式浅色、深色配色都正常
- 没验证：从家具面板拖到图上（HTML5 拖放，自动化点不了），实际用鼠标试一下

2026-11-01 底图、图形、写实（李虎机构 601，测完已恢复空布置、测试文件已删除）：上传底图并保存后布置和房间视图的 `background` 都立刻是 `type: 4` + `src`，去掉后恢复 `type: 2`；文字内容和字号、矩形、圆形（圆角 82.5、直径 165）、写实元素的 `name` 都读回正确。没验证：这些新元素在平台网页端的样子、监控模式和时间回溯里的显示

## 第一版不做的

- 用户端：现在用户端还没有房间平面图，等有了以后直接复用同一套图标
- 组合（type 1）不能编辑，只显示
- 镜像：平台存不下 `scaleX`
- 批量把一间房的装修套到其他房间："复制布置"建房时已经会带上家具，其他情况以后再做
