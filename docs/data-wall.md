# 数据大屏：数据口径（草案）

> 2026-10-19 起草。界面稿在设计画布"用户端"页第四行：**值守态势墙**（护士站电视，实时）、**运营展示墙**（大厅 / 来访参观 / 领导汇报，近 30 天）。
> 原则同其他页面：平台只取设备原始数据和基础记录，所有统计在客户端做；和交接班报告共用"每分钟状态"和"每晚汇总"（见 [handover-and-rounds.md](handover-and-rounds.md) 第 2 节）。

## 1. 两块屏的定位

| | 值守态势墙 | 运营展示墙 |
|---|---|---|
| 放在哪 | 护士站、值班室的电视或第二块显示器 | 大厅、接待室，参观和汇报时用 |
| 看的人 | 护理员、护士长 | 家属、来访者、上级、院长 |
| 时间范围 | 现在 + 今晚 | 近 30 天（可切 7 天 / 本月） |
| 刷新 | 实时推送，秒级 | 每 10 分钟重算一次 |
| 隐私 | 默认显示"姓 + 床位"（张 · 302-1），可切成只显示床位 | **一律不出现姓名**，只有汇总数字 |
| 交互 | 没有鼠标，所有信息直接写在屏上；告警出现时整屏提示 | 多页自动轮播，每页 20 秒 |

两块屏都是用户端的"大屏模式"：全屏、按 1920×1080 设计，等比缩放适配其他分辨率；不显示菜单、窗口按钮；开机自启后直接进入（可选）。

## 2. 值守态势墙

### 2.1 顶部

机构名、当前时间（大字）、实时连接状态。连接中断时整条变成橙色"数据中断，屏上内容停在 HH:mm"，避免大家以为一切正常。

### 2.2 左栏：现在

| 指标 | 口径 |
|---|---|
| 在床 | 当前在床的长者数（`careState` 的 tone = bed），下面拆成睡着 / 醒着 |
| 离床 · 在房间 | 不在床但雷达跟踪到人 |
| 不在房间 | 没有心率呼吸也没有跟踪目标，且设备在线 |
| 暂停监测 | 设备 10 分钟以上没有上报 |
| 未处理告警 | 告警中心里 alertStatus = 1 的数量，红底大字；为 0 时显示绿色"无" |
| 今晚 | 20:00 以后：已入睡人数 / 在住人数、夜间离床累计次数（和平时对比） |

所有人数之和 = 在住长者数，界面上写出总数，方便核对。

### 2.3 中间上：楼层态势（主视觉）

- 按楼层一行，每个房间一个方块，方块里每张床一个圆点，颜色是这位长者的当前状态。
- 房间顺序按房间名自然排序；房间、楼层来自长者档案（`/api/member/pages` 的楼栋、楼层、房间、床位），**只显示有人入住的房间**。
- 有未处理告警的房间：整块红色并闪烁，写告警类型和持续时间。
- 离床 ≥ 15 分钟的床位：圆点外加橙色圈，写"离床 18 分"。
- 机构超过 6 层或 120 个房间时，按楼栋分页轮播。

### 2.4 中间下：今晚全院睡眠条（条形码）

- 每位长者一行细条，从 20:00 到现在，每分钟一格，颜色同交接班报告（睡着、在床醒着、离床在房间、不在房间、暂停监测）。
- 按楼层、床位排序，楼层之间留空。几十条细条叠在一起，一眼就能看出谁整晚没睡、谁反复起夜。
- 数据就是交接班的"每分钟状态"，同一份，不另算。

### 2.5 右栏：告警

| 内容 | 口径 |
|---|---|
| 告警流 | 今天的告警，最新在上，分组 1 / 2 / 4（离线、安装姿态不出现）；5 分钟内同一长者同一类型合并 |
| 处理用时 | 今天已处理告警的 `processAt − createdAt` 中位数 |
| 5 分钟内处理 | 今天告警里 5 分钟内处理的比例（阈值同"需关注规则"里的 timelyMinutes） |

## 3. 运营展示墙（近 30 天）

全部是汇总数字，不出现任何个人信息。

| 指标 | 口径 | 数据 |
|---|---|---|
| 连续安全天数 | 距最近一次"跌倒 / 坐地告警超过 timelyMinutes 才处理"的天数。没有这样的记录时，从开始使用客户端那天算 | 告警记录 |
| 守护时长 | 近 30 天所有长者"有监测数据"的分钟数合计，换算成小时 | 每晚汇总里的监测分钟 |
| 及时发现跌倒 / 坐地 | 近 30 天跌倒、坐地类告警中，处理类型为有效的次数 | 告警记录 |
| 平均处理用时 | 近 30 天已处理告警的中位数，按天画趋势线，标出目标线（5 分钟） | 告警记录 |
| 告警时段分布 | 星期 × 小时的热力图（有效告警次数），用来安排人手 | 告警记录 |
| 误报率 | 处理类型为误报的比例，按周 | 告警记录 + 处理类型对应关系 |
| 睡眠质量 | 每晚睡眠评分分成 4 档（≥80 良好、70–79 一般、60–69 偏低、<60 需关注），按周看各档占比 | 每晚按设备来源取的睡眠报告评分 |
| 夜间平均睡眠时长 | 每晚在床睡着的分钟数（22:00–06:00 之外也算，只要在班次 20:00–08:00 内），全院平均，按天 | 每分钟状态 |
| 夜间离床 | 人均每晚夜间离床次数，按天 | 每晚汇总 |
| 监测覆盖 | 近 30 天每晚监测完整（暂停 < 30 分钟）的人次 / 总人次 | 每晚汇总 |

## 4. 数据从哪来、存在哪

- **实时部分**：用户端现有的长者列表 + 实时推送 + 告警中心，不新增请求。
- **今晚条形码**：交接班的每分钟状态（客户端开着时实时累积，缺口补拉）。
- **近 30 天**：
  - 告警：按天取一次存本机，已结束的天不再取。首次打开补拉 30 天（每个分组每页 1000 条，`getAlertsInRange` 已有）。
  - 睡眠评分：每天早上按设备来源取一次昨夜报告（已有 `getOrgSleepReports`），存本机。
  - 每晚汇总：交接班那边每晚算一次存本机（在床、离床、心率呼吸、监测分钟）。这块屏直接读，不重新拉原始数据。
  - 首次使用时只能补到平台还保留的天数（设备原始数据保留多久还没核实，通信日志只有约一个月），之前的数字显示"—"，并在页脚写"统计自 X 月 X 日起"。
- 多台电脑各自算各自的。态势墙所在的电脑要一直开着客户端，"今晚"和"每晚汇总"才完整。

## 5. 待确认

1. 展示墙要不要放"机构简介 / 床位入住率"之类运营数字（床位总数要从 `/api/bed/options-with-floor` 按楼层取）。
2. 上级单位（民政局、集团）要的多机构汇总屏：平台上级机构看不到下级数据，但超管 token + 各机构的 orgid 可以逐个取。是否要做，账号权限怎么给，再讨论。
3. 态势墙上显示姓氏还是只显示床位，各机构可能要求不同，先做成开关。
