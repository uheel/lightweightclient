# 交接班报告与夜间巡查记录：数据口径（草案）

> 2026-10-19 起草，用户端新增模块"交接班"。界面稿在设计画布"用户端"页第三行（交接班报告、夜间巡查记录、交接班打印版）。
> 原则同其他页面：平台只取设备原始数据和基础记录，所有判断、统计在客户端做；一个班次的数据取一次，两个页面共用。

## 1. 班次与时段

| 项 | 默认 | 说明 |
|---|---|---|
| 班次 | 白班 08:00–20:00，夜班 20:00–08:00 | 可改成三班（08–16 / 16–24 / 00–08）。存在本机，和"需关注规则"一样 |
| 夜间时段 | 22:00–06:00 | 只用来统计"夜间离床""夜间心率呼吸"；班次之外的时间不算 |
| 巡查时刻 | 夜班每 2 小时：22:00、00:00、02:00、04:00、06:00 | 可改成每 1 小时 |
| 范围 | 当前护理区（楼栋 + 楼层），可切到全机构 | 护理区来自长者档案的楼栋、楼层（`/api/member/pages`），和机构概览一致 |

班次没结束时也能打开报告，标"进行中 · 截至 HH:mm"；班次结束后内容固定，存到本机。

## 2. 共用的基础数据：每位长者每分钟的状态

两个页面都从同一份"分钟状态"算出来。每位长者、每分钟一格：

| 字段 | 判断方法 | 来源 |
|---|---|---|
| 在床 | 这一分钟测到心率或呼吸（不看姿态） | 设备原始心率呼吸 `ql-respiratory-rate/pages`，按分钟汇总（`getDeviceVitals`） |
| 离床 · 在房间 | 没有心率呼吸，但雷达跟踪到人 | 姿态时间线 `posture-timeline`，按 userId 1–6 逐个查后合并（`presenceRuns`） |
| 未检测到人 | 两样都没有，且设备在线 | 同上 |
| 暂停监测 | 设备连续 10 分钟以上没有任何上报（与 `LIVE_STALE_MS` 同一个值） | 实时推送；客户端没开着的时段用设备心跳补（见第 6 节，13 型待核实） |
| 睡着 / 醒着 | 在床的分钟里，设备睡眠状态多数为 1 浅睡 / 2 深睡 → 睡着；多数为 3 → 醒着 | 原始心率呼吸记录里的 `sleepStatus` |
| 心率、呼吸 | 这一分钟有效读数（> 0）的平均值；有效读数少于 5 条的分钟不参与统计 | 同上 |
| 卫生间 | 长者另有一台"卫生间"区域的设备，且这一分钟那台设备检测到人 | `member-panoramic` 里设备的 `rangeName`；没有卫生间设备的长者不显示这一项 |

不用的数据，以及原因：
- 平台每分钟心率呼吸汇总 `radar-vital-minute-pages`：每分钟只抓 1 条，不是平均值，还会整分钟丢失。只在原始记录取不到时兜底。
- 睡眠报告里的"离床"：和雷达位置经常对不上（site-analysis.md 有两个例子）。离床一律按上面的分钟状态算，睡眠报告只取评分。
- 平台驾驶舱、需关注名单：不用。

## 3. 交接班报告

### 3.1 本班概况（顶部数字）

| 指标 | 口径 |
|---|---|
| 在住长者 | 当前护理区里已绑定床位的长者数（`member-panoramic`） |
| 监测完整 | 本班"暂停监测"累计少于 30 分钟的长者数。其余的人列入交接事项 |
| 告警 | 本班发生的告警事件数（合并规则见 3.3）。下面分成有效、误报、未处理三类 |
| 平均处理用时 | 本班已处理告警的 `processAt − createdAt` 的中位数。**这是点"处理"的时间，不是到场时间**，界面上写"处理用时"，不写"到场" |
| 夜间离床 | 全护理区夜间离床次数的合计，和"平时"（前 7 晚的中位数）对比 |

### 3.2 每位长者一行

| 列 | 口径 |
|---|---|
| 夜间条 | 班次内每分钟的状态画成一条：在床睡着（深蓝）、在床醒着（浅蓝）、离床在房间（橙）、未检测到人（浅灰）、暂停监测（斜纹）、告警（红色竖线） |
| 上床 | 班次内第一段持续 ≥ 30 分钟的在床，开始的时间 |
| 起床 | 最后一段持续 ≥ 30 分钟的在床，结束的时间；到班次结束还在床则显示"未起床" |
| 夜间离床 | 夜间时段内、上床到起床之间，持续 ≥ 3 分钟的离床段数。短于 3 分钟的空档（翻身、坐床边时心率呼吸会断一下）算在床 |
| 最长离床 | 这些离床段里最长的一段，带开始时间和去向（在房间 / 卫生间 / 未检测到人） |
| 心率 · 呼吸 | 夜间时段内在床分钟的平均值，旁边小字是"平时"（前 7 晚的中位数） |
| 告警 | 本班这位长者的告警事件，显示类型和处理结果 |
| 睡眠评分 | 只在早上 08:00 以后有：按设备来源取当晚睡眠报告的评分（`/api/health/sleep-report`）。白班报告不显示这一列 |

"平时"的规则：取前 7 晚里监测完整（暂停监测 < 30 分钟）的夜晚算中位数，少于 3 晚就不显示对比。每晚的汇总结果很小，存在本机，所以不用每次重新拉 7 晚的原始数据。

### 3.3 告警的处理

- 数据：本班时段内的告警，分组 1 场景、2 事件、4 紧急求助（`getAlertsInRange`，已有）。离线、安装姿态不出现。
- 归属：按告警里的 `members[]` 找长者；没有长者的告警按房间归到这个护理区，单独列在"未关联长者"。
- 合并：同一位长者、同一种告警，5 分钟内连续出现的算一个事件，显示"×3"。处理状态取其中最后一条。
- 状态以班次结束那一刻为准：结束时还没处理的算"未处理，移交下一班"；结束后才处理的，报告里写"交班后 HH:mm 处理"。
- 有效 / 误报：处理类型是各机构自己定的。名字里带"误报"的算误报，其余算有效。可以在设置里改这个对应关系。

### 3.4 需要交接的事项（报告的重点）

自动列出，按下面的顺序排。每一条都能点开，跳到长者详情的那个时间点。

| 顺序 | 事项 | 触发条件（默认，可调） |
|---|---|---|
| 1 | 未处理告警 | 班次结束时 `alertStatus = 1` |
| 2 | 跌倒后观察 | 本班有跌倒、坐地类告警（类型名带"跌倒""坐地"），已处理的也列，提醒下一班留意 |
| 3 | 长时间离床 | 夜间单次离床 ≥ 30 分钟 |
| 4 | 心率呼吸和平时不一样 | 夜间平均心率和平时相差 ≥ 10 次/分，或呼吸相差 ≥ 4 次/分；或者连续 5 分钟的平均心率低于 50、高于 100，呼吸低于 8、高于 24 |
| 5 | 起夜比平时多 | 夜间离床次数 ≥ 3，并且比平时多 2 次以上 |
| 6 | 暂停监测 | 本班累计 ≥ 30 分钟，写出时段，提醒检查（用户端不说"设备离线"） |
| 7 | 护理员备注 | 交班人手写，可以挂在某位长者名下 |

同一位长者有好几条时合成一行，原因用"·"连起来。

### 3.5 交接确认

- 交班人：当前登录账号（姓名）。接班人：输入姓名或从本机用过的名字里选，点"确认接班"。
- 确认后保存一份快照：班次、生成时间、交接事项、备注、交班人、接班人、确认时间。之后数据变化（比如告警被补处理）不改快照，只在页面上提示"确认后有变化"。
- 可以打印或导出 PDF（A4 打印版）。

## 4. 夜间巡查记录

用途：机构需要夜间巡查记录（等级评定、民政检查会看）。雷达在每个巡查时刻自动记一份所有长者的状态，护理员巡查后签到确认。**电子记录和人工巡查分开显示**，不能让设备记录冒充人工巡查。

### 4.1 每个巡查时刻的状态

时刻 T 的状态取 [T−10 分钟, T] 这 10 分钟：

| 状态 | 判断 |
|---|---|
| 告警中 | T 时刻有未处理告警 |
| 暂停监测 | 这 10 分钟里有 5 分钟以上暂停监测 |
| 睡着 | 在床的分钟占多数，且其中睡眠状态多数是浅睡 / 深睡 |
| 在床醒着 | 在床占多数，睡眠状态多数是清醒 |
| 离床 · 在房间 | 离床在房间占多数 |
| 不在房间 | 未检测到人占多数；有卫生间设备且检测到人时写"在卫生间" |

格子里同时显示这 10 分钟的平均心率、呼吸（在床时才有）。

### 4.2 需到场

每个时刻列出需要护理员到场看一下的长者：告警中；暂停监测；不在房间且已持续 ≥ 20 分钟；离床已持续 ≥ 30 分钟。持续时间从分钟状态往前数。

### 4.3 人工巡查签到

- 每个护理区、每个时刻一条：巡查人、签到时间、对需到场长者逐个写结果（例如"在卫生间，已看过"）。
- 签到时间比巡查时刻晚 30 分钟以上的，标"补录"。
- 没签到的时刻在表头显示"未签到"。

## 5. 待确认

1. **交接确认和巡查签到存哪里**：平台上没有能存这类记录的接口。先存本机，可打印、导出 PDF。但多台电脑（每层一台）之间看不到彼此的记录。要共享的话需要一个小后端，或者找平台上能复用的地方。
2. **班次**：机构用两班还是三班？巡查间隔 1 小时还是 2 小时？
3. **"有效 / 误报"的对应关系**：只按名字里有没有"误报"判断，是否够用。
4. **设备在线历史**：客户端没开着的时段，6 型可以用心跳日志补"暂停监测"。13 型的心跳格式还没核对。

## 6. 取数与性能

- **主路径：实时累积。** 用户端开着时，已经订阅了所有长者设备的实时推送。每分钟把在床、跟踪人数、睡眠状态、心率呼吸的平均值汇总成一格，存到本机。一晚一位长者约 720 格，很小。
- **补拉：只补缺口。** 客户端没开着的时段，才去平台取：
  - 原始心率呼吸：每台设备一个时间段一次，一晚约 1.6 万条（未压缩约 2.4 MB），走 `api.getAll` + gzip
  - 姿态时间线：每台设备按 userId 1–6 各一次，单次不超过 24 小时
  - 告警：每个分组每个班次一次
- 补拉按并发上限分批，进度显示在报告顶部（"正在整理 12 / 38 位"）。
- 班次结束后，分钟数据和汇总都存在本机，再打开不再请求平台。"平时"直接用存下的每晚汇总。
- 补拉时要按第 2 节的规则在客户端重新计算，不用平台的每分钟汇总、睡眠报告的离床数据、驾驶舱。
